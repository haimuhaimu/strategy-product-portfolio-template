# 运营项目叙事指南

用于 `rolePreset=operations` 或 hybrid 中偏运营的项目。运营叙事不是活动流水账，而是证明如何识别人群与场景、设计动作、经营过程并形成复用机制。

## 推荐结构

1. **业务目标与人群**：明确生命周期阶段、用户/作者/商家人群和关键行为。
2. **诊断依据**：漏斗、分层、调研、一线反馈、渠道差异或历史复盘。
3. **策略设计**：内容、触达、权益、节奏、渠道、活动机制与频控护栏。
4. **执行闭环**：资源组织、节点、异常处理、跨团队接口和过程看板。
5. **结果验证**：转化、激活、留存、召回、供给、收入、效率或体验指标；写清口径与周期。
6. **机制沉淀**：人群包、SOP、模板、看板、规则、素材库或自动化流程。

## 映射到 v2 字段

- `caseStudy.productMethod`：可承载运营策略、人群分层和执行机制，字段名无需改动。
- `caseStudy.algorithmAndData`：写数据口径、漏斗、对照组、渠道归因和复盘方式。
- `caseStudy.evaluation`：写结果、成本、护栏和适用边界。
- `caseStudy.artifact`：写 SOP、策略表、看板、人群规则等实际资产。

## 避免活动流水账

把“策划—上线—复盘”改写为“发现哪类问题—为什么选择这组动作—如何判断有效—留下什么机制”。执行规模本身不是结果；曝光量也不能自动等于用户价值。

## hybrid 处理

全局 schema 仍只选 `product` 或 `operations`，按目标岗位决定主预设。三个项目可混合，但每个项目内部保持一种主叙事：偏产品强调机制与判断，偏运营强调人群、节奏和经营闭环；在摘要中补一句另一侧能力如何参与。
